# 可玩 MVP 实现记录

## 庭审界面

桌面左栏保存案件摘要、证明要件、陪审员名单与法庭指示。窄屏将卷宗移至记录上方。主栏从上到下依次为案件、进度、分组记录、当前交互。庭审准备、开庭陈述、两方举证、最后陈述、评议、宣告各自成段。举证按案内材料 ID 分组，评议按轮分组。各分段默认展开。玩家点击标题即可折叠或展开；追加发言和完成阶段时保留玩家的选择。标题保留裁定或票数。发言署名按角色 ID 解析，以便旧存档也能显示身份。

## 主持与实时发言

玩家点击开始后，主持器根据已提交状态安排下一项法庭工作。控方先介绍物证或传唤证人、完成主询问并说明证明目的，再开放质证或交叉询问。控方结束举证、控方结案、评议轮次切换及宣告自动执行。等待辩方出牌、询问、发言或澄清时暂停。刷新从最近的已提交状态重新计算下一步。操作取消或出错时清除临时发言，自动环节等待玩家恢复。

正式庭审通过 AI SDK 的 fullStream 读取文本增量，仅将局部 JSON 内的 speech 字段显示给玩家。已校验的完整响应参与裁定和计票。预设发言按短文本块播放，实时正文与提交后的笔录使用同一条目序号，位于对应阶段、材料或评议轮次中。各角色轮换时将焦点交给这条笔录并跟随末尾。辩方工作台承载玩家输入、选证和澄清操作，自动发言期间收起；案件裁决留在笔录末尾。正在执行的命令可以产生多条临时笔录，整项提交后统一入档。

## 首版交付

内置北港仓库失窃案。默认使用离线演示，证人有案件专属回答，演示投票按获采纳的双方材料数量生成。模型模式使用角色设定、庭审记录和可见范围参与推理。密钥仅存于当前页面内存。三种协议的依据见[调查](../research/20261121-browser-llm-tools.md)。

庭审命令先在工作副本执行，再将状态和角色记忆原子写入 IndexedDB 的当前庭记录。同一存档的版本冲突要求重新加载。MVP 保存一个正式庭，每项材料裁决和每轮评议分别作为一个提交单位；长评议中断后从轮首重试。玩家未提交的辩词保存至本标签页的 sessionStorage。创作工作台编辑单个案件及关联角色和候选池，支持 YAML 往返与单项材料独立演练。内置内容和可导入字段以 src/domain/profiles.ts 的校验器为准，MVP 使用单案件 bundle 结构。

## 开发与验证

使用 Node.js 22.22 或更新的兼容版本，在仓库根目录运行 npm ci、npm run dev。npm test 验证材料校验、引擎守卫、四条举证路径、可见范围、计票、失败回滚、恢复和模型适配器的模拟 HTTP 往返；npm run build 执行类型检查并生成 dist。浏览器实测选任、追加开场陈述及刷新恢复，另以独立存档从选任走完双方四项举证与两轮评议，终局为十二票无罪。真实模型测试需要用户选择支持浏览器跨域请求的端点并提供密钥。
